## Como o Guia funciona (roadmap/guia.html)
- Seções no menu lateral: Painel (início), pilares PACE, Cola Rápida, Roadmap Oficial, Plano de Ação, **Configurações**, Sair.
- **Painel de início** é dinâmico: espelha o Plano de Ação — pendentes por mês em ordem de prazo (aviso "atrasada"), concluídas no fim, riscadas, com data e contador.
- **Plano de Ação**: tabela (desktop) / cartões (celular) das 17 ações oficiais (no bundle cifrado) com status/data/observações. Botão **+ Adicionar ação** cria ações pós-imersão com numeração sequencial após as oficiais (18, 19… na ordem de criação; `renumeraNovas` migra dados antigos com 101+): vivem em `execucoes.json` (campo `novas`, com `criadaEm`/`por`), ganham selo NOVA rastreável e podem ser removidas; as 17 oficiais são imutáveis. Ordenação padrão por **prazo**; G×U×T é opção. Botões Exportar/Importar JSON (backup manual).
- **Sincronização automática entre aparelhos** (chave `sapatao-execucoes-v1` no localStorage, formato `{v:2,salvoEm,dados}`): o site lê `roadmap/execucoes.json` pela GitHub Contents API (leitura pública) e, ao alterar, faz PUT/commit automático com mensagem `chore: sincroniza execuções do Planejamento Comercial (automático)`. Vale a última alteração (`salvoEm`). Publicar exige um **fine-grained token do GitHub (Contents: Read/Write só neste repo)** colado uma vez na aba Configurações (localStorage `sapatao-sync-token`); ele também fica guardado **criptografado pela senha do site** em `roadmap/chave.enc.json` (AES-GCM, PBKDF2 600k nos envelopes novos — campo `i`; sem `i` = 310k, ainda abre) — os outros aparelhos recebem a chave sozinhos ao entrar digitando a senha. **Nunca** colocar token em texto claro no código.
- **Configurações** (SÓ ADMIN vê, nos dois painéis): estado da nuvem + chave de publicação; **troca de senha** do usuário logado (valida a atual, 6+ caracteres, grava em `roadmap/usuarios.json` via Contents API — precisa da chave); no PE também a **administração de usuários**; botão Sair.
- **Login** (`auth.js` v3, compartilhado por todos os apps via `window.SAPATAO_APP`): usuário digitado (campo aberto, sem lista) + senha; a lista vive em `roadmap/usuarios.json` (nome, verificador da senha, admin, ativo, permissões `roadmap`/`pe` = edita|followup(PE)|le|nao e `fluxo`/`operacional`/`negociacao`/`mercado` = le|nao (novo usuário nasce sem elas)) com cache local e SEM lista embutida no código. **Verificador**: `kdf:{alg:'pbkdf2-sha256',i:600000,s:<sal 16 bytes b64>,h:<32 bytes b64>}`; o formato antigo `hash` (SHA-256 puro) ainda entra até a pessoa trocar a senha, e toda gravação de senha (minha senha, redefinir, criar usuário — via `sapataoAuth.defineSenha`) grava `kdf` e apaga `hash`. "Manter conectado" grava `{u,h}` no localStorage (`sapatao-roadmap-auth-v1`, `h` = verificador — `sapataoAuth.verif(u)`; formato antigo só-hash ainda vale). Sessões revalidam em segundo plano; sem permissão = tela "Sem acesso"; permissão "le" = interface travada (`body.so-leitura`). A chave de publicação fica criptografada por usuário em `roadmap/chave.enc.json` (v2, envelopes AES-GCM/PBKDF2; o admin gera o envelope ao criar usuário/redefinir senha). `window.sapataoAuth` (user, pw, podeEditar, verif, confere, defineSenha) e `window.sapataoChave` (busca/garante/garantePara) ficam expostos.
- Navegação: "← Página inicial"/"Voltar" sempre levam à central (`../index.html`).

## Servidor próprio (painel.estacaosapatao.com.br, HostGator)
- Endereço novo do site: **https://painel.estacaosapatao.com.br**, publicado pelo workflow `deploy-hostgator.yml` (FTP com TLS, só código; trava se algum `.json` de dados entrar). Segredos: `HOSTGATOR_FTP_HOST`, `HOSTGATOR_FTP_USUARIO`, `HOSTGATOR_FTP_SENHA`.
- `servidor/api/index.php` = porteiro em PHP: login conferido no servidor (PBKDF2 de `usuarios.json`, cookie `__Host-sapatao` (HttpOnly, Secure, SameSite=Strict, um único Set-Cookie), limite de tentativas), permissão por arquivo (`podeLer`/`podeGravar`), filtros (não-admin vê só o próprio usuário e o próprio envelope), mensagens de commit de não-admin só nos formatos do site com o próprio nome (`mensagemSegura`), rota git só admin e só `.json` (troca de chave), registro de acessos sem conteúdo. Token do GitHub só em `painel-privado/config.php` FORA da raiz pública (modelo `servidor/config.exemplo.php`). Detalhes em `servidor/README.md`.
- `servidor/raiz.htaccess` (vira `.htaccess` da raiz): HTTPS, cabeçalhos de segurança, CSP da página inteira (`connect-src 'self'`), bloqueio de `.json/.md/.mjs/...` direto do disco; `fluxo-pessoal/dados.enc.json` sai pela API (rota `pessoal`, app com login próprio).
- **Modo servidor no `auth.js`**: fora de `*.github.io`, `fetch` para `raw.githubusercontent.com/.../main/`, `api.github.com/.../contents/` e `.../git/` vira `/api/raw/`, `/api/contents/`, `/api/git/` (as páginas não mudam); login/eu/sair/senha vão para a API; `sapataoChave.token()` devolve só o marcador `'sessao'`; envelopes guardam só `{k}`. Em `*.github.io` tudo segue como antes (transição).
- Regra: arquivo de dados novo precisa entrar em `podeLer`/`podeGravar` do `index.php`, senão só o admin acessa.

## Segurança (revisão de 23/10/2026)
- **Sair** apaga sessão, chave de publicação e chave dos dados do aparelho. **Manter conectado** é opcional na central (desligado por padrão): sem ele, sessão e chaves ficam só no `sessionStorage` (somem ao fechar a aba). Leitura/gravação das chaves SÓ via `sapataoChave.token()/grava()` e `sapataoCofre.dek()/gravaDek()` — nunca `localStorage` direto.
- Painéis **nunca** gravam a base em claro: sem DEK, `publica()` para com aviso.
- **Senha**: mínimo 12 caracteres e sem nome da pessoa/Sapatão/123456 (`sapataoAuth.senhaProblema`). Senha criada ou redefinida pelo admin grava `trocar:true` no usuário: os painéis mostram "Crie a sua senha" até a pessoa trocar em Configurações (que apaga o campo).
- **Usuário desativado** perde o envelope em `chave.enc.json` ao salvar a lista (`sapataoChave.removeEnvelopes`).
- **Troca da chave dos dados**: cartão "Troca da chave dos dados" nas Configurações (admin). O navegador gera DEK nova, recifra todo `*.json` com `enc:1` (fora `fluxo-pessoal/`) num único commit pela Git Data API, grava `chave-id.json`, recomeça o cofre só com o admin (token NOVO + DEK nova) e apaga `dek.enc.json`. Depois: revogar o token antigo, redefinir a senha de cada usuário e atualizar `SAPATAO_DEK` no ambiente das rotinas. A DEK nova aparece uma vez na tela — nunca em chat.
- **Ferramentas em iframe** (Fluxo, Negociação) recebem uma Content-Security-Policy no `srcdoc`: só scripts inline, fontes do Google, nenhum `connect-src` — script externo ou envio para fora é bloqueado.
- **Push**: o service worker só abre endereços do próprio site; `web-push` com versão fixa nos workflows.
- **Mapa de contas bancárias** (dígitos/contas → empresa) fica CIFRADO em `fluxo/regras.enc.json` → `contas` (`contasBancarias()` do `fluxo-lib`); nunca voltar números de conta para o código.
- Escapar com `esc()` todo texto vindo de `execucoes.json`, `pe-execucoes.json` e `usuarios.json` antes de `innerHTML`, inclusive datas (`fmt()` já escapa).

## Regras de trabalho
- **Antes de commitar, sempre `git pull --rebase`**: o site faz commits automáticos (execucoes.json, auth.js) e o Samuel abre PRs por sessões na nuvem.
- **Abertura rápida dos painéis**: o bundle de conteúdo fica em cache local AINDA CIFRADO (`sapatao-conteudo-roadmap-v1`/`sapatao-conteudo-pe-v1`) — o painel abre do cache e revalida em segundo plano; o Sair limpa esses caches. No login, se a DEK já está no aparelho, o destrava não espera o PBKDF2 da chave de publicação.
- Conflito em `roadmap/execucoes.json`: ficar com a versão remota (é a base de dados viva).
- Repositório é **público** e os DADOS SÃO SENSÍVEIS: todo conteúdo de negócio vive CIFRADO (AES-256-GCM) nos arquivos `*-conteudo.json`, `execucoes.json` e `pe-execucoes.json`. A chave dos dados (DEK) só existe: no localStorage dos aparelhos autorizados (`sapatao-dek-v1`), dentro dos envelopes por usuário (`chave.enc.json`, aberto pela senha) e em `dek.enc.json` (aberto pela chave de publicação). **NUNCA commitar dados de negócio em texto claro** — nem em HTML, nem em JSON, nem em commits antigos (o histórico foi limpo por isso). Os apps cifram/decifram no navegador via `window.sapataoCofre`.
- Nada de tokens ou senhas em texto claro no código.
- Testar localmente com `python3 -m http.server` (as páginas usam `auth.js` externo e fetch — não funcionam bem abrindo o arquivo direto).
- GitHub Pages publica em ~1–2 min após o push; favicon e `auth.js` podem ficar até ~10 min no cache do navegador. Atalho: o botão **Sair** rebusca os arquivos do app direto da rede (fetch `cache:'reload'` + update do sw) — sair e entrar força a versão mais nova.
- Senhas/usuários: gerir SÓ pela página Configurações (admin) — grava `roadmap/usuarios.json` no formato PBKDF2. Não gerar hash à mão nem voltar a pôr SHA-256 no repositório. Os formulários de senha/usuários que sobraram em `roadmap/guia.html` e `estrategia/index.html` não têm mais HTML (código órfão, protegido por `if`).
- Mensagens de commit em português, estilo `feat:`/`fix:`/`chore:`.

## Notificações de follow-up (PE)
- **Tela de notificações**: o sino da topbar abre um painel lateral em CADA painel (`window.abreNotifs`, âncora `#notificacoes`; CSS `.notif-*`/`.sino-*` no tema.css). PE: follow-ups (sem apagados) + ações concluídas (`concluidaPor`), localStorage `sapatao-notif-vistos-v1`. Guia: ações concluídas (`EXECUCOES[id].por`) + ações novas, localStorage `sapatao-notif-roadmap-vistos-v1`. Nos dois: mais recentes primeiro, destaque laranja + contador de não lidos, o que o próprio usuário fez já nasce lido, clicar num item abre a ação, rodapé com link para ativar o push. O toque na notificação push abre a tela do painel certo.
- **Push nativo (Web App)**: `sw.js` + `manifest.json` na raiz; cartão "Notificações no celular" nas Configurações centrais inscreve o aparelho (Push API) e grava a inscrição CIFRADA (AES-GCM + RSA-OAEP) em `roadmap/push-subs.json` (`{u:id,em,env}`). Eventos que notificam (via mensagem do commit automático): follow-up novo no PE (`novo follow-up de X na ação N`), mudança de estado nos DOIS painéis (`X concluiu/reabriu a ação N do ...`) e prazo renegociado no PE (`X renegociou a ação N do ...`). O workflow `.github/workflows/notifica-push.yml` (paths: `pe-execucoes.json` e `execucoes.json`) roda `scripts/notifica-push.mjs`, que decifra as inscrições, **pula os aparelhos do próprio autor** (nome do commit → id via `usuarios.json`) e envia via Web Push com título = o evento ("Novo follow-up de X") e a ação/painel no corpo (o iOS acrescenta "from Sapatão" sozinho — não dá para tirar); toque abre a tela de notificações do painel certo. Cada inscrição pode ter `pref:{fu,est,rng,przo7,przo1,przo0,przoAt}` (caixinhas nas Configurações; `przo` antigo vale como padrão das quatro etapas de prazo) — o robô monta o aviso de cada aparelho só com o que ele deixou ligado.
- **Lembrete diário de prazos**: os painéis publicam `roadmap/calendario.json` (SÓ nº da ação + prazo + status, sem conteúdo — decisão aprovada pelo Samuel) junto do sync; o workflow `lembra-prazos.yml` (cron 12:00 UTC = 9h BRT) roda `scripts/lembra-prazos.mjs` e avisa "vence hoje/amanhã", "vence em 7 dias" (só no dia exato), "atrasou (venceu ontem)" e pega carona nas já atrasadas — cada etapa ligável por aparelho (`przo7/przo1/przo0/przoAt`).
- **Sino na central** (`index.html`): agrega as notificações dos DOIS painéis (busca execuções+conteúdo pela API, decifra no navegador, títulos incluídos), respeita permissões, compartilha o estado de lido com os painéis (mesmas chaves de localStorage) e clica-se para abrir o painel. Eventos ordenados por data+hora (`ord` = campo `em`/`quando`/`h`/`concluidaEm` gravado na criação, formato local `YYYY-MM-DDTHH:MM`). Segredos do repositório: `VAPID_PRIVATE_KEY` e `PUSH_SUBS_PRIVATE_KEY` (chaves privadas; as públicas estão no código). No iPhone só funciona com o site adicionado à Tela de Início. Conteúdo do follow-up NUNCA sai do cofre — o aviso é só autor + nº da ação.
